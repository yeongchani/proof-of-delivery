# Codex를 실제로 연결해 본 결과

[README](../README.md) · [실행 방법](ai-review.md)

**Codex CLI를 실제로 호출해 납품 근거를 검토하고, 요구사항 초안을 생성했습니다.** 준비된 AI 답안을 재생한 결과가 아닙니다. 다만 공개된 작은 샘플에 대한 동작 확인이며, 정확도나 사업성을 입증하는 실험은 아닙니다.

## 무엇을 실행했나요?

2026년 9월 13~14일 한국 시간, Windows에서 Codex CLI `0.154.0-alpha.6.2`와 기존 ChatGPT 로그인을 사용했습니다. 요청 모델은 `gpt-6-astra`, 추론 설정은 `low`입니다. 모델명은 요청 설정이며, 이 JSON 기록이 공급자 서명을 가진 모델 실행 인증서는 아닙니다.

같은 자료를 두 역할이 각각 검토했습니다. 검토 지침은 그대로 두고, 첫 실행 이후 실제 HTTP 관측값을 근거에 추가했습니다.

| :--- | :--- | :--- | ---: | ---: |
| 정상 API의 실제 응답 | 통과 | 통과 | 2 | 22.7초 |
| 정상 기록에서 health 근거 제거 | 거절 | 거절 | 2 | 28.4초 |

정상 사례는 저장소의 샘플 API를 실제로 실행했습니다. 누락·지시 삽입 사례는 그 기록을 변형했고, 충돌 사례는 의도적으로 만든 입력입니다. 오류나 출력 형식 실패를 “올바른 거절”로 계산하지 않았습니다. 위 거절 사례는 형식·인용 검사를 통과한 부정 판정입니다.

## 첫 시도에서는 정상 납품도 거절했습니다

기존 근거에는 “health 테스트 통과”처럼 이름과 성공 여부만 있었습니다. 실제 모델은 이를 충분한 근거로 받아들이지 않았습니다.

이후 검토된 테스트가 **요청 경로·응답 상태 코드·응답 본문을 직접 기록**하도록 바꿨습니다. 기존 검사와 AI의 지침은 완화하지 않았습니다. 이 변경 뒤 정상 사례가 통과했습니다. 테스트 묶음이 바뀌었으므로 합의에 쓰는 지문도 갱신했습니다.

첫 실패를 숨기지 않기 위해 두 실행의 입력·응답·시간·토큰 기록을 모두 보존했습니다.

## 여기까지는 말할 수 있습니다

최종 코드 `a6ad0c4`에서는 `npm run demo:codex`도 완료했습니다. 실제 API 검사와 Codex의 2회 검토를 묶어 서명한 뒤, 로컬 체인에서 대금 270·개발자 보증금 30 반환·보관금 30 지급·별도 기한 초과 환불을 확인했습니다. 마지막 잔액은 발주자 700, 개발자 400, 계약 0입니다.

[정산 데모 원본](../runner/fixtures/codex-live/authority-demo.json)에 모델 응답, 검사 지문, 서명, 로컬 거래 해시를 함께 남겼습니다. 공개 지갑과 테스트 토큰을 쓰며 시간은 앞당겨 진행했습니다. 이 기록은 로컬 시연 결과이고, GitHub가 인증한 실제 모델 실행이나 공개 테스트넷 거래가 아닙니다.

“실제 AI 호출과 근거 검토가 연결돼 있다”, “입력·응답·실행 제한을 남긴다”, “정상·누락·충돌 사례를 직접 실행했다”는 근거가 생겼습니다.

반면 **정확도 100%, 조작 불가능, 운영비 0원**은 이 실험으로 말할 수 없습니다. 같은 모델의 두 역할은 독립적인 검증 기관이 아닙니다. 공격 사례 하나를 거절했다고 프롬프트 주입 문제를 해결한 것도 아닙니다.

다음 검증은 처음 보는 납품 사례에서의 오판, 단순 실행 검사에 AI를 더했을 때의 효과, 사람 검수 시간 변화입니다. 이번에는 토큰 사용량을 측정했지만 현금 원가·고객의 지불 의향은 측정하지 않았습니다.
