# 고객과 원가를 어떻게 확인할 것인가

[README](../README.md)

현재 수수료 10% 미만은 **목표**입니다. 고객 인터뷰 결과, 매출, 운영 비용 절감률을 확보했다고 주장하지 않습니다. 팀의 약 300만 원 분쟁 경험은 문제를 발견한 계기이며 시장 통계가 아닙니다.

## 첫 고객 가설

초기 대상은 테스트로 완료 여부를 확인할 수 있는 소규모 API·보고서 생성·업무 자동화 외주의 발주자와 개발자입니다. 디자인 취향이나 막연한 완성도는 자동 통과 기준에서 제외합니다. 첫 접점으로는 팀이 접근할 수 있는 외주 경험자·소규모 개발팀을 통한 직접 파일럿을 가정합니다. 아직 확보된 고객 명단은 없습니다.

검증할 가설은 '미리 합의한 기준을 만드는 부담과 지갑·토큰 예치의 불편보다, 검수·정산 지연을 줄이는 편익이 큰가'입니다.

## 한 건의 비용 계산

저장소 루트에서 실행합니다.

```bash
npm run cost -- docs/cost-assumptions.example.json
```

예제는 임의의 같은 통화 단위로 작성한 **산술 시나리오**입니다. 모델 요금표나 실제 거래 측정치가 아닙니다. 통화를 섞지 말고 가격·시간·분쟁 확률을 모두 교체해야 합니다.

| 예제 항목             |                     값 |
| --------------------- | ---------------------: |
| 거래액                |                    100 |
| 서비스 수수료율       |                     5% |
| AI 입력/출력 토큰     |            1,000 / 500 |
| 백만 토큰당 가정 가격 |        입력 2 / 출력 4 |
| 실행비 / 체인 수수료  |              0.1 / 0.2 |
| 사람 검토             |         6분, 시간당 20 |
| 분쟁 가정             | 10% 확률, 건당 비용 10 |

이 가정에서 수입 5, 비용 3.304, 차액 1.696입니다. 거래액만 10이면 차액은 -2.804입니다. 고정 운영비·세금·고객 확보비는 포함하지 않았으므로 차액을 순이익이라고 부르지 않습니다. 무분쟁 중재비 0은 검사비·서비스료·체인 수수료가 없다는 뜻이 아닙니다.

AI 결과의 `usage.complete`가 false면 토큰 비용 전체를 측정했다고 보고하면 안 됩니다. 실제 모델·요금·측정일과 사람의 검토 시간을 함께 기록해야 합니다.

## 제출 후 파일럿에서 기록할 항목

| 검증 질문                         | 수집할 근거                                                    |
| --------------------------------- | -------------------------------------------------------------- |
| 최근 외주에서 무엇이 어려웠는가   | 당사자가 설명한 실제 계약·검수·지급 경험, 익명 기록            |
| 사전 검사 기준에 합의할 수 있는가 | 기준 초안 작성 시간, 양측 수정 횟수, 거절 사유                 |
| 서비스가 시간을 줄이는가          | 같은 범위에서 기존 검수와 PoD 검수의 시간 비교                 |
| 누가 비용을 내는가                | 발주자·개발자 각각의 이용·지불 의향과 조건                     |
| 소액 거래에서도 유지 가능한가     | AI·실행·검토·분쟁 원가와 거래액별 차액                         |
| AI가 잘못 통과시키는가            | 미리 정답을 정한 누락·우회·애매한 사례에 대한 오판과 인용 품질 |

가격을 정하기 전에 지불 주체와 거래당 원가를 확인합니다. 소수 인터뷰는 초기 탐색으로 표시하고, 전체 시장의 수요로 일반화하지 않습니다. 실제 계약 정보와 코드는 당사자 동의를 받은 범위에서만 연구·AI 검토에 사용합니다.
