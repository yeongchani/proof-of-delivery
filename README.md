# Proof of Delivery

**외주 개발에서 합의한 납품 기준을 확인하고, 정해진 조건에 따라 대금을 지급합니다.**

[![CI](https://github.com/yeongchani/proof-of-delivery/actions/workflows/ci.yml/badge.svg)](https://github.com/yeongchani/proof-of-delivery/actions/workflows/ci.yml)

“납품은 끝났는데 잔금은 언제 받을 수 있을까?”

PoD는 발주자와 개발자가 완료 기준을 먼저 합의하고, 검사 결과와 이의 신청 여부를 대금 지급에 연결하는 프로젝트입니다. 첫 적용 범위는 기능을 실행해서 확인할 수 있는 소규모 API·업무 자동화 외주입니다.

> **현재는 로컬 프로토타입입니다.** 실제 API 검사와 로컬 테스트 토큰 정산을 실행합니다. 기본 데모의 AI 응답은 테스트용이며 실제 모델의 정확도를 입증하지 않습니다. 테스트넷에는 아직 배포하지 않았습니다.

[실행하기](#직접-실행하기) · [시연 내용](#데모에서-확인할-것) · [코드 안내](docs/implementation.md) · [AI 실행 안내](docs/ai-review.md)

**실제 AI도 연결했습니다.** 설치된 Codex CLI로 정상·누락·판정 유도·충돌 사례를 검토했습니다. 첫 실패와 개선 후 기록을 [실제 호출 결과](docs/codex-live.md)에 함께 공개합니다.

## 어떻게 동작하나요?

1. **기준과 권한에 동의합니다.** 발주자가 검사 기준·검증자·금액·기한을 제안하고 개발자가 승인합니다.
2. **대금과 보증금을 맡깁니다.** 발주자는 대금, 개발자는 계약 이행 보증금을 예치합니다.
3. **납품물을 확인합니다.** 합의한 실행 검사와 소스코드를 두 관점의 AI가 검토합니다. 등록된 검증자가 결과와 근거를 확인하고 서명합니다.
4. **인계와 지급을 함께 처리합니다.** 이의 기간이 끝난 뒤 소스 복호화 키를 공개하는 거래에서 개발자에게 지급합니다. 합의한 일부 금액은 보관 기간 후 지급합니다.

여기서 **러너**는 검사 프로그램, **스마트컨트랙트**는 대금과 지급 규칙을 관리하는 코드입니다. 작업을 나눠 정산하는 한 단계를 **마일스톤**이라고 합니다. 새 계약은 마일스톤마다 하나씩 만듭니다.

검증자가 바뀌려면 양측의 동의가 필요합니다. 권한을 회수하면 새 결과 접수를 멈추고, 이전 서명은 다시 사용할 수 없습니다. 어느 검증자도 수령인이나 지급액을 바꿀 수 없습니다.

통과 결과에는 발주자가, 불통과 결과에는 개발자가 이의를 신청할 수 있습니다. 요구사항이 달라지면 양측이 기존 대금의 정산과 후속 계약에 함께 동의해야 합니다. [계약 운영 절차](docs/authority.md)

## 직접 실행하기

Node.js 22 LTS와 Git이 필요합니다. 기본 데모에는 지갑이나 AI API 키가 필요하지 않습니다.

```bash
git clone https://github.com/yeongchani/proof-of-delivery.git
cd proof-of-delivery
npm ci --ignore-scripts
npm test
npm run demo
```

`npm run demo`는 임시 로컬 체인에서 매번 처음부터 실행합니다. 검사 결과, AI 검토 기록, 서명, 거래 내역은 `runner/out/authority-demo.json`에 저장됩니다.

Codex가 설치·로그인된 컴퓨터에서는 [설정 방법](docs/ai-review.md#codex-cli로-실행)을 따라 실제 AI로도 실행할 수 있습니다.

```bash
npm run codex:smoke -- --output runner/out/my-codex-run
npm run demo:codex
```

첫 명령은 AI 검토 사례와 기준 초안을 확인합니다. 두 번째는 실제 API 검사·Codex 검토·서명·로컬 토큰 정산을 연결합니다. 계정 사용량을 사용하며, 기본 CI에서는 실제 모델을 호출하지 않습니다.

## 데모에서 확인할 것

| 상황                                | 확인하는 결과                                  |
| :---------------------------------- | :--------------------------------------------- |
| 양측 계약 동의                      | 개발자 승인 전에는 대금을 받지 않음            |
| 대금 300·개발자 보증금 30 예치      | 합의한 금액을 계약에 보관                      |
| 실제 API 검사와 테스트용 AI 검토    | 실행 결과·소스 파일·항목별 인용 근거를 함께 기록 |
| 검증자 교체                         | 양측 승인 후에도 이전 검증자의 서명은 거절     |
| 조기 소스 키 공개 시도              | 결과 접수 전과 이의 기간 중 공개를 거절       |
| 3일 이의 기간 후 인계·지급          | 키 공개와 대금 270·보증금 30 지급을 함께 처리, 대금 30 보관 |
| 이후 30일 경과                      | 남은 대금 30 지급, 중복 지급 거절              |
| 다른 계약의 납품 확인이 기한을 넘김 | 발주자 대금과 개발자 보증금을 각각 반환        |

모든 금액은 **USDC를 흉내 낸 테스트 토큰**입니다. 데모는 체인의 시간을 앞당깁니다. 이의 기간에는 실행 결과와 검수 근거를 확인하고, 최종 소스 키는 기간이 끝난 뒤 지급과 함께 공개합니다. 키가 끝내 제공되지 않으면 정해진 인계 기한 후 환불할 수 있습니다.

## 어디까지 믿을 수 있나요?

**계약이 통제하는 것:** 동의한 권한, 고정된 수령인·금액, 서명 재사용 방지, 이의 기간, 보관금, 기한 초과 환불입니다.

**여전히 검증이 필요한 것:** 러너의 보고가 사실인지, AI의 판단이 정확한지, 검사 기준이 충분한지입니다. 코드 지문과 서명은 실행의 진실성을 증명하지 않습니다. TEE·계산 증명은 아직 구현하지 않았습니다.

- AI 인용 검사는 해당 문장이 입력에 존재하는지 확인합니다. 인용이 결론을 뒷받침하는지까지 수학적으로 증명하지 않습니다.
- 납품 코드는 임의의 프로그램입니다. 현재 실행기는 OS 수준의 격리를 제공하지 않으므로, 신뢰하지 않는 코드는 비밀정보가 없는 일회용 환경에서만 검사해야 합니다.
- 분쟁 조정자는 하나입니다. 분쟁 기한까지 응답하지 않으면 각자의 예치금을 돌려줍니다. 이 정책은 피해 책임이나 작업 보상을 판정하지 않습니다.
- 보관금은 지급 지연 기능이며 별도의 30일 하자 판정 기능은 없습니다. 공개된 소스 키는 파일을 가진 누구나 사용할 수 있습니다.
- 지급에는 트랜잭션 호출이 필요합니다. 호출 프로그램은 제공하지만 상시 운영 서비스는 아직 없습니다.
